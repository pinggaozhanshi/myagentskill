# 验证记录（2026-10-24）

两件事分开验证：**脚本**（本包的通用版和试验时真正跑过的原版是否等价），**方法**（四次试验的信号结果和用户盲听）。

## 1. 脚本回归验证

做法（`evidence/regression/`）：

- 用试验留下的真实数据，原版脚本和本包的通用版各跑一遍，逐项比输出。
- 纯信号脚本：JSON / npy / npz / WAV / 打印必须完全一致；另把原版这次的输出和试验当时的存档比，看能不能复现。
- 要连 ACE 的脚本：两版都接 `fake_ace_cli.py`，按同样顺序跑完一个会话，比发出的 ACE 命令序列和写出的文件。
  0.18 的命令（`vocalpitch write / read / voicing / set-voicing`、`vocal-to-midi`、`clip list`）按《绯红》实测的行为模拟：
  断开标记存在两段中点、写进去的辅音长度和音符时值读得回来、个别音拒绝改辅音长度。
- 和原版逐字节相同的脚本：比校验值。

| 套件 | 数据 | 结果 | 内容 |
|---|---|---|---|
| `run_regression.py` | 《妄想感傷代償連盟》（CLI 0.17 时代） | **47 / 47** | 21 个逐字节相同的脚本；22 个信号脚本；A/B 与盲听包；3 个 ACE 会话（单轨建工程到第 1 轮 `--apply`、两轨读回导出与和声照抄、第 2 轮离线写音高） |
| `run_regression_feihong.py` | 《绯红》（CLI 0.18.7） | **42 / 42** | 14 个逐字节相同的脚本；14 个信号脚本（含混音）；混音检查；真的 RMVPE；离线改辅音；5 个 ACE 会话（建工程 + G2P + 读回、第 1 轮 `--apply`、在线写音高、音节结尾轮、Vocal to MIDI）；新功能与新检查各一项（下面） |

新写或新加的功能没有原版可比，单独测：

- `round1_timing.py --skip 179`：只有 #179 的句尾释放移到“人工排除”，其余计划不变；不加 `--skip` 时句尾释放的决定与《绯红》真跑的计划相同；
- `tempo_fit.py`：《绯红》的节拍分析上拟合 101.998 BPM、按 102 残差中位 5.7 ms / 最大 39.8 ms、拍 0 在 0.9649 s
  （文档里当时临时算的是 101.998 / 6 / 40 ms / 0.9647 s；三段的分法不同，这里的三段平均残差 −0.6 / −1.4 / +2.1 ms）；
- `target_check.py`：四条真写进 ACE 过的目标曲线（《绯红》，《妄想感傷代償連盟》试验段 / 完整副歌主唱 / 和声）都通过；
  把《绯红》最长的音整体抬高 12 半音，被拦下并指出这个音；
- `voicing_clear.py`：两段固定清成 0 段并保存，命令序列正确；
- `endings_apply.py` 的未保存改动检查：撤销记录里有用户的改动 → 退出、一个辅音都不改；只有自己上次中断留下的辅音长度 → 接着做完；
- `ace_dump.py`：命令和输出（音素行数 = 非延长音的音符数）。

通用版有意多出的 ACE 调用只有一条：`round1_timing.py --apply` 另存之前的 `project dirty`（确认开着的是 state 里那个已保存的工程）。
比对命令序列时从通用版里去掉这一条，并要求它确实出现（两套里各 1 次）。

结果文件：`results_wangxiang_20261024.json`、`results_feihong_20261024.json`。
