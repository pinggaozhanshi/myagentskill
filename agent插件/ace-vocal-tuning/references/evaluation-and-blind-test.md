# 评估与盲听：信号检查只排错，好不好听由用户盲听定

我们（agent）听不见。所有检查都是信号测量，有两个用途：

1. 抓错：唱错音、错字、八度、断声、吃掉的元音、被唱过去的休止；
2. 量和参考的距离：音高误差、时值差。

**“更接近原唱”不等于“更好听”**（调教版照搬了原唱的滑音习惯）。哪个版本更好，只由用户盲听决定。每份报告都写明“没有人耳确认”的部分。

## 每轮要跑的信号检查

| 检查 | 脚本 | 看什么 | 正常 / 门槛 |
|---|---|---|---|
| 读回 | `ace_readback.py` | 音符、歌词逐个一致；音素全部解析；音素行数 = 音符数 − 延长音数 | 0 处不一致；读音逐字过一遍（多音字） |
| 导出 | `ace_export.py` | 非静音比例 | ≥ 20%，否则多半是静音 / 独奏没处理好 |
| 音高 | `pitch_eval.py`（Praat、RMVPE 各一份） | 误差中位、p90、±50 音分内比例；逐音“比基线好 / 差 > 30 音分”的个数；> 600 音分的帧单独计数 | 比基线差的音 = 0，或逐个解释 |
| 颤音叠加 | `pitch_eval.py` | 连续 ≥ 250 ms 的段，去趋势后 4–9 Hz 的均方根（音分） | 合成不明显大于原唱（四次都略平于原唱） |
| 断声 | `glitch_check.py` | 音符中间参考有声、合成连续无声 ≥ 20 ms | 两侧都有声的才算，列秒数请用户听；只有一个提取器看到的多半是误判 |
| 时值 | `timing_voicing.py` → `compare_timing.py` | 被改的音更近 / 更远（差 ≥ 5 ms 才算）；没改的音中位数是否变了 | 更远的记作退步；**停顿消失（休止被唱过去）是错误**，下一轮改回 |
| 结尾（第 2 轮之后） | `vowel_coverage.py`、`voicing_check.py`、`ending_check.py` | 原唱在唱、合成没声音；被固定成无声的元音；结尾 AI 音高尾巴 | 见 `round-endings.md` 的触发线 |
| 表情参数轮 | `voice_features.py` 等 | 锁定后的噪声底、各参数的实测 / 预测 | 见 `round3-expression.md` |
| 成品混音 | `mix_check.py` | 各段人声对伴奏、原唱残留上限、开头 2 秒、总览图 | 走势和原曲一致，差在 1.5 dB 内（用户另有要求时按用户的） |

断点、断声、可疑结尾都要列出时间（成品时间和原曲时间），交给用户时请他重点听这些地方。

## A/B 与盲听（`make_ab.py`）

- **干声**：各版本和参考人声统一到 −20 LUFS（ITU-R BS.1770，pyloudnorm 积分响度）；峰值超过 −1 dBFS 时整组一起降低。
- **带伴奏**（只做标明版本的试听；要做带伴奏盲听时另外随机）：
  - 人声电平 = 原曲里人声的实际电平：官方人声分轨，或不去混响的分离人声；
  - **两人合唱的歌按两人的总电平放**。《超级超级超级讨厌》第一版按初音单人的电平放（比伴奏低 7.2 dB），两人合计其实只低 1.5 dB，
    用户说“伴奏太响，听不见人声”，这一对作废，改了重做；
  - 干声没经过混音时放进伴奏可能听不清：《反乌托邦》咬字最要紧的 1–6 kHz 比原唱人声低约 5–6 dB，用户决定跳过带伴奏、按干声判断。
- **盲听**：
  1. 基线和调教版用 `secrets` 随机分配甲 / 乙。`make_ab.py` 一次调用只出一对干声盲听（给出的第一个和最后一个版本）；
     要几对就调用几次，每次换输出目录和 key 文件，各自随机、互不相关。
  2. 答案只写进 `work/` 下的 key 文件，**用户回答之前不读**；也不打印盲听文件的电平。
  3. 揭晓后把盲听文件的 SHA-256 记进报告。
- **问用户的话**：每一对里哪个更好（或听不出差别），以及哪里不对。他的原话照抄进 `docs/pilot-report.md`。

## 门槛

- **试验段通过** = 干声盲听调教版胜。听不出差别或基线胜：停下找原因，不推广到整首。
- **加工类的改动**（表情参数、EQ 提亮）只在盲听被选中时才进成品；差别很小时留不加工的版本。三次都是用户选了不加工的那一版（见下表）。
- 用户对第一次交付的反馈也是一次“听”，按同样的方式记原话、诊断、改了再给（《绯红》）。

## 四次试验的结果

| 曲目 | 干声盲听 | 带伴奏 | 之后 |
|---|---|---|---|
| 《超级超级超级讨厌》（2026-10-18，日语） | 乙（r2）明显更好 → 调教版胜 | 第一版作废（人声太小）；第二版甲（r2）更好 → 调教版胜 | — |
| 《反乌托邦》（2026-10-19，中文） | 甲（r2）更好 → 调教版胜 | “人声听不清，没法判断”，用户决定跳过 | 第 3 轮表情参数：“乙的前半段是经过改动的，感觉声音比较沙哑，但现在无需改动” → 留 r2 |
| 《妄想感傷代償連盟》（2026-10-21，日语） | 乙（r2）更好 → 调教版胜；补充“原唱唱的更加干脆” | 没做（沿用上一首按干声判断） | “干脆”轮：“差别很小，我感觉是甲”（甲 = r2）→ 留 r2；EQ 提亮：干声、带伴奏都选不提亮的 r2，“还是听不出来太大差别” |
| 《绯红》（2026-10-24，日语，一分钟版） | 没做（前三首都胜，直接交付 r2 混音） | 用户听 v1：“音乐有点响，并且有些音节的结尾没处理好，重新改一下” | v2：伴奏再降 4 dB（另附 −7 dB）+ 音节结尾轮；用户还没回复 |

《绯红》的教训：方法验证过不等于这首没问题。第 2 轮之后的结尾检查当时还没有，信号上看得出的问题被用户先听出来了。
以后不做盲听时，交付前也把所有检查跑完，并告诉用户要重点听哪些地方。
