# 经验索引：症状 → 原因 → 怎么办

出处：超 = 《超级超级超级讨厌》（2026-10-18）、反 = 《反乌托邦》（10-19）、妄 = 《妄想感傷代償連盟》（10-21）、
绯 = 《绯红》（10-24）、刷 = 《刷到》原创（10-24，另一会话）、呐 = 《呐呐呐》（11-05）。细节在各篇 reference 里。

## 测量与参考

| 症状 | 原因 | 怎么办 | 出处 |
|---|---|---|---|
| 低音区、轻的乐句被判成无声，测量全部返工 | Praat 默认静音阈值 0.03（相对整段最大振幅） | 一律走 `common.praat_grid`（阈值 0.005） | 超 |
| F0 网格上有空洞，20 秒 862 次碰撞 | Praat 帧时刻落在半格上，取整撞格 | 按时间插值到网格（`praat_grid` 已做） | 超 |
| 原样分离的人声 67% 的帧落到低八度、和谱面只吻合 7% | 带混响、叠着低八度 | 音高、时值参考只用去混响那组（72%）；原样那组只用来定混音电平 | 妄 |
| 副歌长音上两个提取器都落到低八度 | 原曲叠了低八度人声 | 目标曲线允许折回八度（> 9 半音、平移后 ≤ 2 半音）；单音差 12 用谐波判断 | 妄 |
| RMVPE 报 ACE 输出有 20–60 ms 的元音中间断声 | RMVPE 对 ACE 合成声的通病 | 断声以 Praat 为准，只有一个提取器看到的多半是误判 | 绯 |
| RMVPE 跑不起来 | 研究目录 venv 没有 torch；系统 Python 有 torch 没有 torchaudio | `rmvpe_run.py`（torchaudio 替身） | 绯 |

## 谱面与读音

| 症状 | 原因 | 怎么办 | 出处 |
|---|---|---|---|
| 歌词 `no` 变成 False | PyYAML 按 YAML 1.1 读 USTX | 用 ruamel.yaml（YAML 1.2） | 超 |
| 从第 33 小节起整段高一个八度 | USTX 谱面本身错 | `note_check.py` 的八度候选，整段改 | 超 |
| “ベタ打ち”谱面、和声谱面音不准 | 投稿谱面不保证准 | 逐音对参考 F0；和声用 `hamo_check.py` 的谐波证据 | 妄 |
| Vocal to MIDI 的歌词约四分之一不对、两三个音节并成一个音 | 识别器的音节能力弱（音高很准） | 按网格量化，对官方读音逐拍对齐，按网格点的能量凹陷、清音间隙拆音 | 绯 |
| 还给你唱成 hái、句尾呢唱成 ni | G2P 按字的默认读音，不看上下文 | 读回音素逐字核对，`phoneme set` 覆盖 | 刷 |
| 命令行写不进空歌词 | CLI 不收空歌词 | 用「-」，和 ACE 里清空歌词的“空音符”效果相同 | 妄 |
| 时值轮把网格误差当辅音问题去“修” | 网格（BPM、偏移）没定准 | 两类证据定网格，调教前冻结 | 全部 |

## 第 1 轮：时值

| 症状 | 原因 | 怎么办 | 出处 |
|---|---|---|---|
| 句尾释放差点把 0.25 s 的字拉成 1.6 s | 长休止里的分离残留被当成“前一元音结束” | 释放差 > 300 ms 不改 | 反 |
| 快歌里拉长辅音把前一个音吃没 | 220 BPM 十六分只有 68 ms | 拉长不超过前一个音的 70% | 妄 |
| 一个「あ」被下一个字 81 ms 的 t 吃掉大半，起先误判成起音 / 表情问题 | 辅音太长 | 缩短辅音（26 ms 后有声比例 22% → 91%）；先查时值再怀疑表情 | 超 |
| 促音的停顿没了（135 → 10 ms） | 句尾释放把休止压到约 118 ms，ACE 连唱过去 | 促音、短休止前不延长；漏了就下一轮 `--revert` | 绯 |
| 中文字被拖长 / 日语字被切短 | 方向因语言而异：中文清声母偏短，日语清辅音偏长 | 不预设方向，按测量双向改 | 反、妄 |

## 第 2 轮与之后：音高、结尾

| 症状 | 原因 | 怎么办 | 出处 |
|---|---|---|---|
| 粗检查把大音程过渡、闭塞下沉、句尾回落都判成错音 | 用了“\|delta\| > 7 的占比” | 改成“中段中位 > 6 半音”或“> 9.5 半音持续 > 50 ms” | 超 |
| 第 1 轮只改辅音，周边乐句的音高也变了 | ACE 按片段重新生成 AI 音高 / 参数 | 第 1 轮的 A/B 不是纯时值对比；看“基线 vs 最终” | 妄 |
| 结尾的元音尾巴变成嘶声、闭塞 | 辅音默认 80–157 ms，原唱只提前 0–51 ms | 音节结尾轮规则 E | 绯 |
| 改了辅音，元音还是无声 | 在线写音高把当时的无声判断固定住了 | 最后一步 `set-voicing --mode auto` | 绯 |
| 结尾最后几十毫秒音高下滑、乱飘 | 曲线只写在原唱有声处，结尾交给 ACE 自己的音高 | 规则 F 补全曲线 | 绯 |
| 乐句结尾 10 ms 内掉到数字静音 | ACE 2.1.9 的渲染行为 | 混音时 35 ms 淡出（`--end-fade-ms`） | 绯 |

## 第 3 轮：表情参数

| 症状 | 原因 | 怎么办 | 出处 |
|---|---|---|---|
| 标定出的“气声效果”大得离谱、方向还反 | 没锁参数，测到的是别的参数的漂移 | 先把四个参数都锁成绝对值曲线再标定 | 反 |
| 锁定写不进去 | direct 层只收 ≥ 0.3 的张力 / 假声，AI 值 65–73% 低于 0.3 | 离线写 `realTension` / `realFalsetto`（`patch_params.py`） | 反 |
| 用户一听就认出改动版，“沙哑” | 气声推到 ×1.5，谐噪比被原唱的混响、混音压低，不能照着追 | 低音区先只降假声，气声 ≤ ×1.2 | 反 |
| “干脆”只用力度改，盲听差别很小 | 起音由声码器决定改不动；差距更可能在高频 | 不默认做；提亮也没被选中 | 妄 |

## 盲听、混音、交付

| 症状 | 原因 | 怎么办 | 出处 |
|---|---|---|---|
| “伴奏太响，听不见人声”，盲听作废 | 合唱曲按单人电平放（−7.2 dB，合计是 −1.5 dB） | 按原曲人声的总电平放 | 超 |
| 带伴奏人声听不清，没法判断 | 干声没混音，1–6 kHz 比原唱人声低 5–6 dB | 用混音链；或按干声判断 | 反 |
| “音乐有点响” | 按原曲比例混，人声只比伴奏高 0.25 dB | 翻唱默认 `--inst-db -4`，再给一版更低伴奏的备选 | 绯 |
| 方法验证过，用户第一次听还是挑出问题 | 没做结尾检查就交付 | 交付前跑完所有检查，告诉用户重点听哪里 | 绯 |
| 重开工程后渲染和交付版对不上 | ACE 重开后渲染会变（p90 1.5 dB、最大 8.7 dB），锁参数也回不去 | 成品导出前先保存、重开、再渲染；修改只拼接改动的乐句 | 妄 |
| r 和 l 的辅音指标分不开 | 同一工程两次渲染就差 2.5 dB，比 r→l 的差大 | 读音只靠读回确认，写明没有人耳确认 | 妄 |

## 《呐呐呐》全曲（2026-11-05，双人齐唱 + 和声，145 BPM）

| 症状 | 原因 | 怎么办 | 出处 |
|---|---|---|---|
| 全曲一半的字发糊，Whisper 把“メンション”听成“メーション” | 辅音默认 75–226 ms，比前一个音的元音还长；`nv`（ん）后接 sh 只剩 16 ms | 全曲显式写辅音：L = 原唱间隙 + 校准量（实际间隙 ≈ L − 10～30 ms，k t d 差得多、s sh 差得少）；前音 ≤ 110 ms 时 L ≤ 46 ms（擦音 50），其他 L ≤ 前音一半 | 呐 |
| 按原唱间隙直接写后 k 被听成 g | 写入值不是实际无声间隙 | 先渲染一次量“写入值 vs 实际间隙”，再校准 | 呐 |
| 103 ms 的音元音中段塌 13–26 dB、有声比例 0.9 → 0.6 | 后一个辅音 L ≥ 55 ms（放宽保护到 40% 时出现） | 上限见上一行，改回 50% 再收紧 | 呐 |
| ん + で 的句子字变糊 | d 占掉 ん 一半时长 | ん 后 d b g ≤ 30 ms、j z ≤ 40 ms | 呐 |
| CLI 报“carries no head consonant lengths” | 没合成过的音 headConsonants 是空列表 | 离线全曲一次写入（项目 `final_patch_heads.py`），ACE 重开后保留 | 呐 |
| 长音写法（べ+え）有 −9～−12 dB 的再起音 | 纯元音音符会重新起音 | 同元音、不跨词的音改「-」 | 呐 |
| 两位主唱齐唱发糊 | 各自的辅音、AI 音高不同 | 三轨同位置同字写同样的辅音长度，齐唱写同一条音高曲线 | 呐 |
| “未决”的音其实是错音 | 这些句子去混响后几乎没声，提取器无值 | 用未去混响的分离人声再跑 RMVPE，三提取器一致值和频谱峰核对 UST | 呐 |
| 写的原唱曲线和 ACE 音符差 15 ms | 分离人声来自 YouTube 音频，比官方伴奏 WAV 晚 | 用器乐起音分别量两条时间轴，参考提前对应帧数；混音不平移 | 呐 |
| 字听不清但人声已靠前 | ACE 2–8 kHz 比原唱暗 6–11 dB | 不提亮人声，人声在唱时压伴奏 2–8 kHz 3–4 dB（探针 40 句变好、0 句变差）；单抬辅音没用 | 呐 |
| 用户：“所有呐呐呐里只有开头那句最符合原唱” | 原唱 7 处是同一条曲线；只有开头是独唱，其他 6 处有和声，“离谱面 > 1.25 半音的参考不用”把 3 半音的上滑和提前下滑切了 | 写目标前跑 `repeat_phrases.py`，重复句抄没被盖着的那次；和声按音高折线映射（`round2-pitch.md`“重复句”） | 呐 |
| 音高离目标只有 3 音分，用户还是听出不像 | 指标量的是离自己写的目标，目标错了看不出 | 同谱面的句子互相比，差 > 1 半音、持续 > 100 ms 的要解释；用户说“某处最像”时，先比那一处和其他处的曲线，别先猜音色 | 呐 |
| 滑音变成来回的台阶（67 → 69 → 67.9 → 69） | 滑音中段的参考被保护规则删掉，退回谱面基线 | 整段滑音用模板，不要逐帧退回基线 | 呐 |
| 同一句两次重复，其中一次中间掉了 2.8 个半音 | 多个提取器一致地抓到了别的声音，“三提取器一致”也会错 | 重复句互相核对，抄干净的那次 | 呐 |
| 局部写音高后，写入范围末尾多了 `[tick, null]` | `vocalpitch write` 只替换首尾锚点之间，并在末尾断开曲线（约 4 ms 缺口） | 读出整段片段的曲线，改完整段写回 | 呐 |

吐字的客观代理量：项目 `scripts/asr_probe.py`（Whisper 对正确歌词的逐词元概率 + 自由听写），只比同一句的不同版本，不代表好听。

## ACE 操作

| 症状 | 原因 | 怎么办 | 出处 |
|---|---|---|---|
| 导出的文件没声音 / 不渲染 | 被静音的轨、有别的轨独奏时不渲染 | 渲染前查静音、独奏（`ace_render.py`） | 全部 |
| 工程存到了意想不到的地方 | `save-as` 再套一层同名文件夹；相对路径按 ACE 安装目录解析 | 一律绝对路径，以返回的 `savedPath` 为准 | 全部 |
| 分离完找不到分出来的轨 | Stem Splitter `--wait` 的返回值不带轨道 UUID | `stems_collect.py` 从 `Samples/Processed/*.ogg` 认领 | 妄 |
| 离线写的工程打开后变成“未保存” | ACE 当临时工程打开，脚本切换静音 | 撤销记录里只有脚本自己的静音 / 独奏才可丢弃，否则停下 | 反 |
| 用户在 ACE 里有没保存的改动 | — | 另存为新工程把改动带过去，原文件不动，永远不替用户丢弃 | 妄 |
| 个别辅音报 `PHONEME_TIMINGS_UNAVAILABLE` | 前一个音只有元音，ACE 不开放时长（合成后也不） | 离线改 `headConsonants`（`patch_consonants.py`） | 绯 |
| V1 的音素 span 一直是 not-synthesized | V1 没有这项状态 | 不能拿它判断“已合成” | 超 |
