# 混音与交付

调教只动 ACE 工程；混音只处理导出的干声（效果链停用导出），两边分开记录。混音脚本 `mix_vocals.py`，检查 `mix_check.py`。

## 处理链（`mix_vocals.py`，两首成品用过，数值固定）

| 环节 | 设置 |
|---|---|
| 主唱 | 100 Hz 二阶高通 → 压缩：RMS 检测 5 ms、阈值 = 有声段电平中位数、3:1、6 dB 软拐点、启动 5 ms、释放 80 ms（《妄想感傷代償連盟》有声段增益衰减中位 1.4 dB，最多 6.8 dB） |
| 和声 | 同样处理，响度比主唱低 8 dB，6 kHz 以上再降 2 dB |
| 混响 | 人声一起送，300 Hz–8 kHz 带通后卷积合成的立体声混响（T60 1.4 s、预延迟 25 ms、固定随机种子），比干声低 15 dB（LUFS） |
| 延迟 | 只送主唱，5 kHz 低通，八分音符左右交替 3 次，比干声低 22 dB |
| 电平 | 人声总线对伴奏的响度差 = 原曲同一段里人声分轨对伴奏的差（《妄想感傷代償連盟》−0.65 dB、《绯红》+0.25 dB），再按 `--inst-db` 调 |
| 母带 | 整体增益到约 −10 LUFS，前瞻 5 ms 限幅（4 倍过采样测峰），峰值 ≤ −1 dBTP；两首成品都是 −10.5 LUFS、−1.0 dBTP |
| 区间 | 默认按小节（第一个音所在小节往前 1 小节到最后一个音之后的强拍 + 3 s 淡出）；`--cut-to-vocal` 从人声第一个非静音帧前 20 ms 开始；`--end-at` 指定结束时间 |

不追商业母带的响度：《绯红》原曲同一段 −7.8 LUFS，成品轻 2.7 dB。

## 三条已定下来的判断

1. **音色不提亮**（三次盲听，见 `evaluation-and-blind-test.md`）：
   - 起因：长期平均频谱显示 r2 在 2.5–5 kHz 比原唱暗 3–9 dB、8 kHz 以上暗 9–18 dB；
   - 试过的 EQ（`eq_brighten.py`）：峰形 3300 Hz、Q 1.0、+3.3 dB，高架 8 kHz、+6.5 dB，补一半差距，齿音不比原唱刺；
   - 结果：干声、带伴奏两对都选了不提亮的版本，“还是听不出来太大差别”。
   以后 EQ 只当可选的 A/B，不进默认链。
2. **人声要比原曲比例更靠前**（《绯红》，用户听 v1：“音乐有点响”）：
   v1 人声总线只比伴奏高 0.25 dB（按原曲比例），v2 用 `--inst-db -4`（人声高 4.25 dB），另附 `-7` 的备选。用户还没选。
   以前《超级超级超级讨厌》也因为人声太小判断不了。所以翻唱要显式传 `--inst-db -4`（脚本不给这个选项时是 0 = 按原曲比例），
   再用 `--inst-db -7 --suffix _伴奏再低3dB` 出一版备选，交付时说明两版的差别。
3. **乐句结尾的硬切要淡出**（ACE 2.1.9）：`--end-fade-ms 35` 自动找“10 ms 内掉到数字静音”的结尾，在掉落点前加 35 ms 余弦淡出，
   交付的干声也带上；报告的 `end_fades` 写出位置（成品时间和原曲时间），说明里要提。2.1.8 渲染的休止有 −50～−60 dB 底噪，没有这个问题。

## 开头 2 秒

用户的习惯：开头 2 秒没有特点、没有情绪就划走（抖音看 2 秒跳出，前 1 秒要有事件）。
所以一分钟版不留长前奏：《绯红》不留 27 秒钢琴前奏，从人声第一个字前 20 ms 切入（`--cut-to-vocal`），第一个 0.5 s 里人声总线 −13.9 dB。
`mix_check.py` 报告开头每 0.5 s 的电平。

## 检查（`mix_check.py`，信号指标）

| 项 | 《妄想感傷代償連盟》 | 《绯红》 |
|---|---|---|
| 分离伴奏里与原唱旋律同音高的帧（原唱残留的上限） | 0.7% | 5.5%（钢琴很重，钢琴弹旋律音也算进来） |
| 各段人声比伴奏（成品 / 原曲） | 铺垫 +1.7 / +0.3、副歌 +0.2 / +0.2、后段 −1.1 / −1.9 dB | v1 主歌 −0.4 / −0.2、铺垫 +1.5 / +0.1、副歌 +1.1 / +0.5 dB；v2 +3.6、+5.1、+4.9 dB |

按原曲比例混时走势应该和原曲相同、差在 1.5 dB 内；加了 `--inst-db` 就按设定的差看。原唱残留只在分离伴奏时看（官方伴奏不用）：
先按 `mix_report` 的 `window_sec` 截出伴奏，跑 `rmvpe_run.py`，再给 `mix_check.py`。

## 交付清单

| 文件 | 说明 |
|---|---|
| `<曲名>_混音.wav` / `.mp3` | 48 kHz / 24-bit 立体声；MP3 320 kbps |
| `<曲名>_干声.wav` / `.mp3` | 同一区间的调教版干声，单声道，不加处理（只有结尾淡出） |
| `人声总线.wav` | 干声 + 混响 + 延迟，已乘母带增益、未经限幅：以后拿到官方伴奏可以直接重混 |
| `mix_report.json`、混音检查 JSON、总览图 | 区间（原曲时间）、电平、淡出位置、检查结果 |
| 说明（`docs/` 下的报告） | 做了什么、信号检查结果、**哪些没有人耳确认**；用户原话；校验值 |

- 成品导出前先保存、重开工程、再渲染导出（重开后渲染会变，见 `revisions.md`），以后局部修改才能拼接。
- 所有成品的字节数和 SHA-256 记进 `docs/source-ledger.md`；新版本另起文件名（`_v2`），旧版原样保留。
- 伴奏是分离出来的就写明，并说明换官方伴奏重混的办法。公开发布前核对原曲的二创规约并署名。
