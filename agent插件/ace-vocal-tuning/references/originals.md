# 没有原唱参考的歌（原创曲）

本工作流的第 1、2 轮都以原唱为尺子：时值按原唱的有声 / 无声边界改，音高照原唱的 F0 写。原创曲没有原唱，这两轮不适用，
能用的只有“不靠参考”的那部分：谱面和读音核对、安全地写进 ACE、可复现的导出、抓错的检查。

下面的做法来自《刷到》（洛天依中文原创，`D:\自媒体\刷到_洛天依原创_20261022\`，另一个会话在做，2026-10-24 还在进行），
工具在那个项目里，没拷进本工作流。

## 谱面与读音

- 谱面是自己写的 `song.json`：人声每个音一个汉字，或「-」延长前一个字（「-」不能打头）。写进 ACE 前先校验这两条。
- **倒字检查**（`scripts/checks/tones.py`，pypinyin 按整句取声调，含变调；多音字按词读，如「划走」的划读 huá）：
  - 前一字的收尾高度：一声、二声高，三声、四声低；后一字的起头高度：一声高、二声中、三声低、四声高。轻声和「-」不参与比较。
  - 期望上行却下行 ≥ 2 半音、期望下行却上行 ≥ 3 半音、期望平却跳 ≥ 5 半音：标记。
  - 一个字唱几个音时：二声净下行 ≥ 2、四声净上行 ≥ 2、一声音域 ≥ 3 半音：标记。
  - 标记出来的由写词的人决定改词还是改旋律；这是信号规则，不是听感。
- **多音字**：G2P 不看上下文。《刷到》读回发现「还给你」唱成 hái、句尾「呢」唱成 ni。
  `song.json` 的音符可以写 `"phonemes": ["h", "uan"]`，建工程时用 `phoneme set` 覆盖并读回核对。

## 写进 ACE 与导出

- 安全检查、读回与本工作流相同：音符、歌词逐个一致；「-」没有自己的音素行。
- 导出：停用效果链 → 保存 → **重开工程** → 再渲染导出（重开后渲染会变，见 `revisions.md`）；重开后再核一次每个音的读音没变。
- 片段从 tick 0 开始，导出的干声和编曲分轨同一个 0 点。

## 检查与评估

- 能做的检查：读回、导出非静音比例、乐句结尾硬切（2.1.9，混音时淡出）、开头 2 秒有没有事件（用户的习惯）。
- 没有参考，音高误差、时值差、元音覆盖这些“和原唱比”的指标都没有。
- 改了什么（例如手画音高、颤音、呼吸、表情参数）才有 A/B：基线和改动版音量对齐后随机盲听（`make_ab.py` 的做法），用户选中才保留。

## 没验证过的方向

ACE 0.18 的命令行有 `vocalpitch carbon-copy` / `modulate`（照 AI 音高画一段再放大起伏）、`vocalpitch set-vibrato`（逐音颤音），
可以在没有参考时做“手工调教”；本工作流的几次试验都没用过，效果只能靠盲听判断。

## 用户对原创的其他要求（记忆里的，和调教无关但会影响成品）

- 开头 2 秒要有特点、有情绪，前 1 秒要有事件。
- 参考别的歌只借感觉（情绪、上头的原因），不搬招牌词、口头禅、旋律。
- 歌词要有深度：核心意象、具体画面、语言感染力，不写“刷到你、点赞、算法”一类的自媒体梗。
