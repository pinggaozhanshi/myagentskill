# 交付后的修改

用户听完成品提意见是常态（《妄想感傷代償連盟》v2、v3，《绯红》v2）。改法的核心是：**只动用户说的地方，其余和上一版逐采样相同**。

## 步骤

1. **记原话、写清理解**。原话照抄进报告；时间、字、音这类要换算的写出你的理解。
   - 例：“在1.31s和1.22s处”理解为原曲 1:31、1:22（成品里 0:38.6、0:29.9）。
   - 例：“音乐有点响”理解为伴奏相对人声太响，不是整体音量，并说明如果指整体音量就另调。
   - 真有两种解释、做错代价大时先问。
2. **分清改的是哪一层**：

   | 用户说的 | 改哪里 |
   |---|---|
   | 歌词、读音 | `note set-grapheme --note-uuid … --lyrics '[…]' [--language CHN\|JPN]` / `phoneme set`；读回逐音核对 |
   | 两个音断开了、要连上 | 后一个音改延长音「-」（用户说的“空音符”：清空歌词的延长音；命令行不收空歌词，「-」效果相同） |
   | 结尾没处理好 | 音节结尾轮（`round-endings.md`） |
   | 伴奏太响、人声太小 | 混音 `--inst-db`，另给一版备选 |
   | 开头的音乐剪掉、直接切入人声 | 混音 `--cut-to-vocal` |

3. **新开一轮工程**：从交付工程另存（`full_r3` → `full_r4`）。用户在 ACE 里有没保存的改动时，从开着的工程**另存为新工程**把改动带过去，
   原文件不动；再逐音对照谱面，弄清他改了什么（《妄想感傷代償連盟》v3：用户清空了 3 个音的歌词、把伴奏轨拉到 −30.9 dB 试听，“裁剪音符”最后没留下时值变化）。
4. **渲染前先保存、关掉、重开**，再渲染导出（下一节）。
5. **只把改动的乐句拼进交付版**（`splice_main.py`），没改的部分与交付版逐采样相同。
6. **核对**：改动处的信号（交界断开深度、读回的音素）、整体音高评估、断声、混音检查、与上一版成品逐段的差
   （`examples/ust_妄想感傷代償連盟/ra_fix_check.py`、`mix_diff.py` 的做法）。
7. **新文件名**（`_v2`、`_v3`），旧版原样保留；校验值记进来源台账。

## ACE 重开工程再渲染，结果会变

- 《妄想感傷代償連盟》：r2 一点不改、重开再渲染一次，副歌各音电平与交付版差 p90 1.5 dB、最大 8.7 dB，波形完全不同。
- 之后的各次渲染彼此逐采样相同（改了歌词的 r3，副歌和重渲染的 r2 逐采样相同），所以变化来自“重开”，不是改动本身。
- 把四个表情参数锁回 r2 的 AI 值也回不到交付版（反而多出 −22 dB 的差）。
- 交付版当时是“离线写完、ACE 第一次打开就渲染”的；推测 ACE 保存时重写了工程里的曲线（未查证）。

所以：**成品导出前，先在 ACE 里保存、重开一次再渲染导出**（命令见 `ace-cli.md` 的“重开”一节；离线改过的文件要先让 ACE 保存一次再重开）。
这样以后局部修改时，新渲染里没改的部分能和交付版逐采样对上。《绯红》r2 照做了；r3 是离线补丁后第一次打开就导出的，以后改它之前先核对能不能对上。

## 拼接（`splice_main.py`）

- 替换段：含改动的音、且前后紧接（tick 相连）的整串音；起止落在前后的休止里（最后一串到片段末尾）。
- 接口：休止内（两端各让开 20 ms）找两版包络都最低的位置，20 ms 余弦交叉淡化；要求淡化范围内两版都低于 −45 dBFS。
  2.1.8 的休止里有 −50～−60 dBFS 的底噪（接口处实测 −51.6～−60.4 dBFS）；2.1.9 的休止是数字静音，没在 2.1.9 上拼接过。
- 读回：替换段以外与交付版逐采样相同，段内（淡化以外）与新渲染逐采样相同。
- 段里没改、但和改动连着唱（中间没有休止）的音会带着重渲染的浮动：《妄想感傷代償連盟》10 个音 |差| 中位 0.75 dB、最大 1.8 dB。

## 案例

**《妄想感傷代償連盟》v2**（用户听 v1）：“这个ららららら的音是lalala还是nanana。我感觉像是nanana，有点不像原曲，把这个音改正，
并在1.31s和1.22s处这两个断开的音节合并上”。
- 20 个「ら」改中文「啦」（读回 l a，原来是日语的 r）；两处合并：后一个音改「-」，接着前一个「啦」的元音唱。
- 交界断开深度：−8.1 → +1.7 dB、−5.9 → +1.1 dB（越负断得越开）。
- 读音只靠读回确认：辅音段的频谱指标分不出 r 和 l——同一个工程两次渲染就差 2.5 dB，比 r 改 l 的差（0.7 dB）还大。

**《妄想感傷代償連盟》v3**（用户听 v2）：“把‘拉’全改成‘呐’把我感觉更像原曲一点，上次我提到的那个断开的地方直接用空音符延长前面的音符……
并把开头的那一点音乐剪掉，直接切入人声”。
- 用户在 ACE 里已清空 3 个音的歌词（未保存）→ 另存 full_r4 带过去；16 个音改「呐」（读回 n a），两处都是「呐」+ 两个延长音。
- 「呐」的辅音段指标 21.4 dB（「ら」16.0、「啦」14.0），鼻音这次分得清；改过的 20 个音比 v1 平均弱 1.7 dB（「呐」本身渲染得偏弱）。
- 混音从人声第一个非静音帧前 20 ms 开始；有没有更像原曲，没有人耳确认。

**《呐呐呐》v3**（用户听 v2）：“我感觉在所有呐呐呐中只有全曲开头那一句呐呐呐最符合原唱，修改所有的呐呐呐为开头的那个并总结下原因进入工作流”。
- 先比开头和其他几处**写进工程的曲线**，不先猜音色：一比就看出开头有 3 半音的起音上滑，其他 6 处是平的。再用原唱和官方和声确认 7 处本来是同一条曲线。
- “全部改成开头那个”不能照字面换声音：10 处分三种旋律，开头是独唱、其他是齐唱加和声，还有两处高一个半音。同谱面的抄曲线，旋律不同的按同样做法修，37.05 秒已经贴原唱就不动。
- 只改音高曲线，整串音拼进 v2；成品只有这 8 段和 v2 不同，开头本身没动。音量走向没有强行对齐，先量了原唱：原唱这几处很平，开头的起伏不是它像的原因。
- 用户指出的是一处，原因影响的是一类：交付时报告还有哪些句子有同样的问题，由用户决定要不要改。

**《绯红》v2**（用户听 v1）：“音乐有点响，并且有些音节的结尾没处理好，重新改一下”。
- 伴奏相对人声再降 4 dB，另附再降 3 dB 的备选；
- 音节结尾轮：34 个辅音按原唱缩短、音高曲线补全、清掉固定的无声，5 处硬切淡出；
- 结尾问题改的是整条片段的辅音和曲线，不是几句，所以整条重渲染（r3），没有拼接。
