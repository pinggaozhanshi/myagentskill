# 歌曲替换、同步与交付

## 歌曲来源

确定用户指定的完整歌曲导出，区分干声、伴奏、试唱片段、MP3与无损混音。优先已接受的完整无损导出。核对当前工程歌词与字幕快照的音符位置、末位置及文字，包含用户最后改过的句子。替换音轨不意味着获得改词、调声、变速或重新混音授权。

## ACE / MIDI坐标

ACE `note-content` 的`pos/endPos`是clip-local，相对该片段完整范围的`geometry.pos`。

- 音符全局tick = `geometry.pos + note.pos`。
- `clipPos`是全幅内的可视区起点；`clipBegin = pos + clipPos`。它用于可见范围筛选，不应再从音符全局tick扣掉。
- 88 BPM/480 PPQN案例：pos960、clipPos480、note.pos720，global=1680tick，时间2.386364s。不能套成1200tick。
- 常速秒数 = `tick * 60 / (BPM * PPQN)`；变速工程按tempo map分段积分，不能拿单一BPM计算全曲。

读取工具当前help/API文档以确定实际坐标语义。换软件不要套ACE公式；记录tempo、起点、trim与导出范围。CLI可用时优先正式CLI；ACE连接断开先检查进程/访问状态，再用用户已配置的替代接口，不能擅自关闭脏工程或丢弃未保存修改。

## 测偏移和漂移

用同源伴奏、鼓/节拍或共有声部在前、中、后多个窗口比较。主唱居中时`L-R`侧声道常有助于降低不同演唱的干扰；它是该项目可用的办法，不适用于单声道、侧声道过静或伴奏不同的任务。

本包工具定义`lag = other_event_time - reference_event_time`，等价于在other中滑动reference片段求最佳相关。

- lag负：新歌事件更早，应给新歌补正延迟。
- lag正：新歌事件更晚，可能需要提前新歌；先确认要裁去的开头有无有效声音。
- 应用平移量 = `-lag`。务必用合成信号或有明确起点的片段核对符号，别混用不同库的lag定义。
- 各窗口lag一致：固定平移；后段越来越偏：检查采样率、tempo、剪辑/导出起点或变速。只有证据支持时才做拉伸/局部对齐。
- 总时长差先检查静音尾、混响和编码填充；不能按158.992/160.010直接压缩整首歌。若额外长度含有效人声或尾音，不能为了贴合PV而直接裁掉。先保留完整音轨，并在用户授权范围内决定是否延展画面；仅有明确的静音余量才可裁除。

伴奏对齐还需歌词身份和句时刻核对。列出每句文本、工程音符时刻和PV显示窗口，区分字幕提前显示、辅音提前、音符起点与实际发声；不要宣称按音符表就完成了盲听辨字。

## 只换音轨

复制已接受视频码流；新歌从无损源编码一遍交付格式。用版本化临时文件写出，编码结束及验证通过后再成为最终输出。不要为换歌曲重绘或重编码整幅PV。

比较视频包哈希、codec extradata、参数和规范化PTS/DTS；必要时解码比较像素。相同帧数/fps只证明时间结构，不足以证明画面相同。

在成片中重新测多窗口偏移；检查视频末帧、音频首尾、静音/尾音与源文件哈希。AAC/MP3编码延迟和padding要用解码时刻/容器语义解释，不能把补偿误算两次。

## 电平与交付

采用现有混音时先保留音量；测编码后的sample peak/true peak、综合响度和声道。不要宣称B站强制固定LUFS，也不要把本案−14.2LUFS/−1.5dBTP作为所有曲子的目标。编码后削波才根据证据采取小幅调整并记录。

交付记录包括输入版本/哈希、改动范围、尺寸/帧率/帧数/时序、采用素材、歌词快照、平移量及符号、编码参数、实际编码检查、剩余限制和可播放成片地址。注明哪些是数值检查、哪些是实际观看/试听；未执行的检查不可写成通过。
